# 学习算法（algorithmVersion 2，保留 v1 历史兼容）

代码：`lib/services/study_scheduler.dart`（纯函数）、`lib/services/study_session.dart`
测试：`test/study_scheduler_test.dart`、`test/study_flow_test.dart`、`test/data_correctness_test.dart`

本阶段**保留** Phase 1 的五级阶梯，不迁移 FSRS，也不替换调度器。

## 状态与阶梯

`1 / 3 / 7 / 14 / 30` 天；答对上一级，模糊退一级并在 6 小时后重现，不认识回到底部
并在 30 分钟后重现。长间隔按本地午夜计算（"1 天"就是明天），短间隔用精确时长。
状态：`newWord(0) / learning(1) / review(2) / relearning(3)`。
每个会话同一单词最多额外重复 2 次。

## 每日口径（Phase 2 明确化）

- 每日目标是**设备全局**（`dailyNewTarget` / `dailyReviewLimit`），UI 明确标注。
- 词书只决定"从哪些词里取"，不改变每日额度。
- `TodayProgress`：
  - `newDone` — 今天学习过的**不同**新词；
  - `newRemainingAllowance` — `目标 - newDone`，下限 0；
  - `unlearnedTotal` — 范围内实际未学单词数；
  - `newAvailableToday` — `min(额度, 未学)`，这是 UI 显示的"今日可学新词"；
  - `dueTotal` — 到期总数；
  - `reviewAvailableToday` — `min(复习额度, 到期)`；
  - `backlog` — 超出复习额度的到期数，顺延到明天。
- `hasWork == false` 时不显示可点击的"开始学习"。
- 队列口径与首页一致：`buildQueue` 同样把新词数限制为 `min(剩余额度, 未学数)`。

## 专项复习

`SpecialReview.hard`（困难词：错/模糊 ≥ 1）、`recentMistakes`（14 天内答错）、
`inBook`（指定词书内已学词）是**显式入口**，不会挤占普通到期队列。

- 专项仍按剩余复习额度取词（额度为 0 时允许最多 20 词的短专项），
  所以额度仍是全局一致的；
- 新专项作答保留真实历史与正确率，但不增加普通每日额度；答对不会继续拉长现有长期间隔，遗忘/模糊仍按短期规则处理。v1 历史按原规则重放；
- 专项**不在会话内重复**失败卡，避免"N 个词"计数失真；
- 每条事件保留 `mode = special-*`，可在词条历史中看到，也可同步。

## 手动操作

- "标记为已掌握"写入一条 `known` 作答事件（`mode = manual-mastered`），
  按算法推进阶梯。它不是直接改派生状态，因此同步合并后不会丢失。
- "重置学习进度"写入一条 `mode = reset` 事件。重放到该事件时清空此前累计，
  单词回到未学习；原始作答历史保留，可在词条详情查看。

## 重建与同步

`learning_states` 可由 `review_events` 确定性重建：

- 顺序 `(causalOrder, answeredAt, deviceId, id)`；历史计数为 0，新事件在事务内递增已知最大计数，保留真实时间并抵抗同毫秒/时钟回拨导致的因果颠倒；
- `algorithmVersion` 存在事件上，未来换算法时可解释历史；
- 合并与重建在同一事务内完成；`SyncCoordinator` 另有 pending 标记恢复路径。

## 刷新时机

应用启动、从后台恢复、跨过本地午夜、词库修改、学习完成、备份导入与同步完成后，
首页与统计的 providers 会被 invalidate。测试使用 `FixedClock.nextDay()` 验证跨日行为。


## Phase 3 事件与会话

- `manual-mastered`：设为 30 天掌握状态，保留真实答题次数，不增加正确次数/每日额度。
- `manual-unmastered`：取消之前未撤销的人工掌握影响；从真实历史重建，保留全部事件。
- `reset`：清空派生进度，原始历史统计仍存在。
- `undo:<eventId>`：追加引用事件；重放和统计排除被引用答题，不删除已同步记录。同一目标多次撤销幂等。
- `repeat`：当轮复练保留真实答题；答对保留原长期 interval 和 due，不多占新词目标。
- 事件按 `(answeredAt, deviceId, id)` 排序；未来算法/未知事件类型拒绝导入。
- 同日恢复队列/位置/复练；跨日或学习目标版本改变时按当前额度重新建队列；过滤已删除词、已删词书、已移出关系以及同步后的已完成卡。
- 撤销范围是当前会话最近一次合法提交；队列因删除/同步变化重新过滤后不保留不再合法的撤销位置。

新作答保存作者日界锚点并跨时区重放；旧库优先从准确 due 回填，未知旧备份按作答 UTC 日期午夜确定性回退，来源可向更准确值升级。香港作者进程、纽约导入进程的绝对 due 相同测试已通过。旧备份无法恢复从未记录的原时区信息，不能声称精确还原。冲刺及新练习模式尚未开放。


首页“继续学习”仅展示当日且学习目标版本仍一致的本机会话；“跳过”不写事件、不消耗每日额度。作答前复查词条/词书/关联是否仍存在。撤销事件、派生状态及会话快照在同一事务更新，快照故障注入验证完整回滚后可重试。

## 本轮总结与错词复练

会话只保存本轮真实作答事件 ID，作答、撤销与快照在同一事务更新；失败回滚同时恢复内存中的 ID 列表。总结按这些 ID 查询，排除撤销和管理事件，不按时间窗口猜测归属，也不混入其他页面/设备的同期作答。分别显示新词/复习的独立词数、总独立词数、实际作答次数、认识/模糊/不认识、复练作答数和正确率。经过时间明确包含暂停，在本轮完成时固定。

本轮曾模糊或不认识的词可进入独立 `special-session-mistakes` 队列，按原会话词书范围过滤删除/移出项。每词一次，用户明确点击作答才记录；不重复增加普通每日新词数，认识不会把已有长间隔继续推远。未完成队列可同日恢复，跨日或计划失效时不从全局错词偷偷重建本轮队列。原全局会话与收藏入口使用明确的全部词书范围，不被之后选择的活动词书误缩小。
