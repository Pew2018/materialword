# 单向云备份历史删除

历史页每份文件均可单独删除，包括最近两份；确认框显示名称与时间。
“清理旧备份（保留最近两份）”默认不自动执行。先完整读取列表，按应用文件名中的
有效 UTC 时间倒序，同时间按文件名倒序稳定决胜；不足三份时没有删除请求。
确认框列出保留项、删除数量和可获取的总大小。

批量清理先下载、解析并校验拟保留的两份文件；未知版本、损坏或上传结果不确定的
新文件使清理停止，不能挤掉旧保留项。确认后重读完整列表并核对其摘要，保留文件
再次读取核对 SHA-256；列表、保留内容或目标变化即中止。

上传、列举、下载、删除和清理共用协调器互斥。目标和凭据在操作开始时固定，
每次请求前复核配置指纹；旧历史列表不能在改账号、bucket、目录或凭据后删除。
仅处理当前目录中符合 materialword-backup-时间-UUID.json 规则的文件。
双向同步对象、探测对象、子目录和无关文件均不参与删除。

S3 ListObjectsV2 循环读取 continuation token，缺失/重复 token、重复对象或缺少
IsTruncated 时停止。WebDAV 使用 Depth:1 的完整标准列表；207 中任何失败状态、
已声明的分页、限制或截断均拒绝批量清理，不能猜测服务商的私有分页协议。
静默截断且不声明的服务端行为无法由标准 WebDAV 检出，应先核对服务商限制。

删除请求之后重新完整列举，只把确认不再可见的对象计为删除。403 等错误保留为失败；
DELETE 响应丢失但刷新后对象消失则可确认删除；刷新本身失败则报告结果待确认。
配置中途变化时停止后续删除并报告待确认结果。部分成功不会显示“全部完成”。

S3 DELETE 不携带 versionId：开启版本控制时通常创建 delete marker，旧对象版本
仍存在，可能继续计费。本功能不枚举或清空历史版本。需要 s3:ListBucket、
s3:GetObject、s3:DeleteObject 权限；WebDAV 需列举、读取与删除权限。

删除测试使用替身及本机 HTTP/HTTPS 测试服务，没有删除用户真实云端对象。
