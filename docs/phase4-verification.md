## 4D 大数据性能

### 分段定位（4D-02）

`test/phase4_performance_test.dart` 的 `onPhase` 钩子在 20000 词 / 100000 事件合并中实测（Debug、内存 SQLite、单机独立运行）：

| 阶段 | 优化前 | 优化后 |
|---|---:|---:|
| 校验（`validate`） | 1003 ms | 1003 ms |
| 词条合并（`words`） | — | 2967 ms |
| 事件合并（`events`） | — | 1460 ms |
| 学习状态重放（`replay`） | — | 1532 ms |
| 书籍/关联/元数据 | <2 ms | <2 ms |
| **合并总计** | **13759 ms** | **6866 ms** |

优化前的分段值无法事后还原（同一二进制才可比），因此优化前只引用总耗时；优化后的分段值来自当前源码。`words` 是当前最大单项，主要成本是每个词 3–5 次单行查询（`resolve` ×2、`byNormalized`、`remember` ×2），已定位但本轮未改。

### 实施的两项优化

1. **事件合并：一次读取现存 ID 集合 + 批量插入。**
   原实现为每条事件执行一次 `SELECT ... WHERE id = ?` 加一次单行 `INSERT`，100001 条事件即约 20 万次往返。现在先一次读出全部事件 ID（仅 ID，约数 MB），新事件攒批 500 条插入；重复 ID 才回读该行做字段比较。数据集内部重复 ID 通过待插入表识别。
2. **状态重放：按 400 词分块读取事件。**
   原实现每个受影响词一次独立查询，20000 词即 20000 次带排序的查询。现在分块查询并按词分组，重放函数抽成纯函数 `_replay()`，单词语义与批量语义共用同一份代码，保证两者不可能产生不同结果。

两项都不改变事务边界、事件顺序、撤销语义、字段冲突规则或内容哈希。
