# 文案规范（Copywriting Guidelines）

MaterialWord 的界面语言参考 Apple 自有应用与系统设置：简单、明确、准确、克制，偶尔亲切。
**只借鉴语言风格，不改变现有 Material Design 2 Classic 视觉。**

## 1. 三条硬规则

1. **说用户能做的事，不说代码做了什么。**
   - ✅ 导入失败，现有数据未更改。
   - ❌ 导入失败（事务已回滚，未修改任何数据）：FormatException…
2. **一个概念只有一个名字。** 见 `docs/ui/localization-glossary.md`。
3. **风险提示不得缩短到失真。** 删除、恢复、同步冲突必须写清：改什么、留什么、是否影响其他设备、能否恢复、同步是否暂停。

## 2. 简洁

| 不要 | 要 |
| --- | --- |
| 当前没有可用的学习任务队列。 | 暂无学习任务。 |
| 当前学习词书 | 学习词书 |
| 今日可学新词 | 可学新词 |
| 设置考试日期与目标词书，独立安排重点练习 | 为考试制定复习计划 |

* 标题已表达的信息，不要在副标题重复。
* 设置项作用已足够明确时可以没有副标题（强调色只保留一句「更改应用的主题颜色。」）。

## 3. 明确

| 不要 | 要 |
| --- | --- |
| 确认执行操作。 | 删除 |
| 已完成派生学习状态重建。 | 学习进度已更新。 |
| 请先填写仓库 owner / repo / 分支 / 数据文件路径 | 请输入 GitHub 用户名或组织。 |

* 按钮用动词或动宾短语，不用「确定」「执行」。
* 校验提示必须指向具体字段，不能把多个字段合并成一句话。

## 4. 用户导向与技术分层

* 普通界面禁止出现：ETag、If-Match、SHA、Contents API、条件写入、退避、字段版本、Tombstone、事务、Keychain/Keystore 内部机制、SQLite 异常、堆栈、内部路径。
* 这些信息保留在「同步诊断」→「技术详情」与导出的诊断报告中。
* 用户提示与诊断信息是两层：`AppErrorCode` 决定提示，`detail` 只进日志。

## 5. 亲切的限度

允许：今日任务已完成。 / 今天的学习进度已保存。 / 暂时没有需要复习的单词。
禁止：太棒了！！！ / 你真的超级厉害！ / 赶紧开始背单词吧！ / 今天又是元气满满的一天！

## 6. 空状态必须区分原因

同一句「今日任务已完成」不能覆盖所有情况。至少区分：

* 今日目标已完成；
* 当前范围内没有未学新词；
* 词书为空 / 尚未导入单词（首次使用）；
* 没有到期复习；
* 已达到复习上限（并说明顺延到明天）。

## 7. 数量与时间

* 数量必须带单位并支持单复数：`1 word / 2 words`，`{count} 个单词`。
* 统计名称不得合并不同指标：作答次数、作答单词数、本轮复练次数、已撤销作答是四个概念。
* 用时若包含暂停必须写明「（含暂停）」，不得用精简文案改变统计口径。

## 8. 英文写作

* 用自然英语，不做中文逐字翻译。
  - ✅ Today / Word Lists / All Words / Exam Prep / Start Studying / Session Complete / Sync Now
  - ❌ This Day / Vocabulary Management / Only Do Review / Synchronize Immediately / Study Has Been Completed
* 页面标题、主要按钮、设置名称用 Title Case；说明正文用 sentence case。
* 文案里不出现「点击这里」式指引；按钮文字本身要能独立说明动作。

## 9. 大小写与标点

* 中文句子用全角标点；英文句子用半角标点。
* 一句提示只有一个句号，不用感叹号。
* 不在句子中间插入代码标识（例如 `etag` 反引号），需要时改为普通词「版本标识」。

## 10. 提交流程检查表

- [ ] 新文案是否已在 `app_en.arb` 与 `app_zh.arb` 同时存在？
- [ ] 是否用了 `context.l10n`，而不是硬编码字符串？
- [ ] 是否用 `AppErrorCode` 判断分支，而不是比较文案？
- [ ] 数量/时间是否用了 ARB 参数（含复数）？
- [ ] 危险操作是否说明了数据影响与可恢复性？
- [ ] 英文是否读起来像原生应用？
